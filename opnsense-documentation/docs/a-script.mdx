# A script

The box is already the server. A script on your laptop opens HTTPS to the LAN address. The browser does a cousin of the same call when you press Save.

Read [Use the API](https://docs.opnsense.org/development/how-tos/api.html) next to this page. If a sentence here and that page disagree, trust the page and the version you booted.

## Make a key before you write curl

**System → Access → Users**, edit the user (a lab can use `root`), API **+**, download the text file once. It contains `key=` and `secret=`. The appliance will not show that secret again. If the file is lost, create another key.

The user must be allowed to open the GUI page that owns the endpoint. A correct key with no privilege still fails.

## One read, first

```bash
curl -k -u "KEY:SECRET" https://192.168.1.1/api/core/firmware/status
```

`-k` skips verification of the factory certificate. Take it off when you trust a certificate you installed yourself. JSON means the call landed. An HTML login page means you hit the GUI, not the API result. A `401` means the pair or the privilege is wrong.

Do not put the secret in the query string. Basic auth belongs in the header curl builds from `-u`.

## When a POST is fair

Do the task once in the GUI so you know it is allowed. Repeat it with GET routes until the replies look familiar. Only then send a POST such as a firmware update or a new group. Those change the appliance. The shapes are on [the calls](/docs/the-calls).

The controllers live in [opnsense/core](https://github.com/opnsense/core). A path `/api/core/firmware/status` is the core firmware controller, command `status`. The generated index on [the API reference](https://docs.opnsense.org/development/api.html) lists many more modules than this booklet.
