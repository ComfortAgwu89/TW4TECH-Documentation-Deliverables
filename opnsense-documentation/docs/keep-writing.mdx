# Keep writing

Plugins extend the firewall. **System → Firmware → Plugins** is where they are installed. `os-virtualbox` is the lab example. This booklet does not ship a plugin. If you write one, follow the layout in [opnsense/core](https://github.com/opnsense/core) and the development chapters on [docs.opnsense.org](https://docs.opnsense.org/). New API paths show up in the generated index after the plugin is really installed. Document the path only then.

## A new chapter on this site

The site is the `opnsense-documentation` folder.

1. Add a file under `docs/`, for example `docs/notes.mdx`, with a `title` in the front matter.
2. Add `'notes'` to the list in `sidebars.js`. The id is the path without `.mdx`.
3. If the cover or the footer should mention it, edit `src/pages/index.js` or `docusaurus.config.js`.
4. From this folder: `npm install` once, then `npm start`.

`onBrokenLinks` is `throw`. A link to a chapter that does not exist fails `npm run build`. Either add the file or remove the link.

When a step fails on a clean ISO, write down the OPNsense version, the hypervisor, and the URL you called. Check that sentence against the official page for that version before you publish it.
